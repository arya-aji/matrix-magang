# 1. Product Definition

## 1.1 Objective

Build a lightweight internal application for managing and monitoring interns.

The primary question the application must answer is:

> **"What is each intern working on today, what is the progress, and is there anything blocking them?"**

The application is NOT intended to be a full HRIS.

The MVP focuses on:

1. Intern management
2. Mentor management
3. Task management
4. Task progress
5. Daily activity/check-in
6. Mentor monitoring
7. Feedback
8. Basic performance overview

Performance evaluation is based on accumulated work evidence rather than being an isolated scoring system.

---

# 2. Core Product Principles

## 2.1 Mobile First

Mobile is the primary interface.

All primary actions must work comfortably on a 360px-wide viewport.

Target:

* 360px
* 390px
* 412px
* 768px
* 1280px+

Do not design desktop first and shrink it to mobile.

---

## 2.2 Fast

Application should feel instant for normal CRUD operations.

Requirements:

* Server-rendered pages wherever possible
* Minimal client-side JavaScript
* Avoid unnecessary global state
* Avoid large UI libraries beyond shadcn/ui
* Use pagination for large lists
* Use database indexes
* Use skeleton states instead of blocking spinners
* Use optimistic UI only where it improves UX
* Avoid unnecessary API calls

---

## 2.3 Simple

The application should not feel like enterprise HR software.

Prefer:

```text
Task
Progress
Activity
Feedback
```

over complicated workflows.

# 4. User Roles

There are three roles.

```text
ADMIN
MENTOR
INTERN
```

## ADMIN

Can:

* Manage users
* Manage interns
* Manage mentors
* Manage departments
* Assign mentors
* Create/edit/delete tasks
* View all activities
* View all interns
* Manage performance criteria

---

## MENTOR

Can:

* View assigned interns
* Create tasks for assigned interns
* Update tasks
* View daily activities
* Provide feedback
* View performance history
* Update task status

Cannot:

* Manage users
* Manage system configuration
* Access unrelated interns

---

## INTERN

Can:

* View own tasks
* Update own task progress
* Update task status where permitted
* Submit daily activity
* View own activity history
* View mentor feedback
* View own performance information

Cannot:

* View other interns' private information
* Create users
* Assign tasks to other interns
* Modify mentor/admin data

---

# 26. Daily Activity Rules

An intern can:

* Create today's activity
* Edit today's activity
* Submit today's activity

After submission:

* Activity remains editable during MVP
* `updated_at` records changes

Future version may lock submitted activity.

Past dates can be viewed.

Past activities should not be editable by interns unless explicitly enabled.

# 27. Today's Activity

The system timezone for business logic is:

```text
Asia/Jakarta
```

# 28. Task Progress Rules

Valid range:

```text
0 - 100
```

Recommended behavior:

```text
0-1%       → TODO
2-99%      → IN_PROGRESS
100%       → COMPLETED
```

However, explicit status changes are allowed.

Example:

```text
Progress 60%
Status BLOCKED
```

This is valid.

When setting:

```text
COMPLETED
```

automatically:

```text
progress = 100
completed_at = current timestamp
```

When moving away from COMPLETED:

```text
completed_at = null
```

---

# 29. Blocker Logic

A task is considered blocked if:

```text
status === BLOCKED
```

Dashboard should surface blocked tasks prominently.

Do not infer "blocked" merely from low progress.

---

# 30. Overdue Logic

Task is overdue when:

```text
due_date < today
AND status != COMPLETED
```

Do not store `is_overdue`.

Calculate it dynamically.

---

# 31. Internship Progress

Calculate:

```text
elapsedDays =
today - startDate

totalDays =
endDate - startDate

internshipProgress =
elapsedDays / totalDays * 100
```

Clamp to:

```text
0 - 100
```

If status is COMPLETED:

```text
100%
```

If UPCOMING:

```text
0%
```

# 34. Performance Calculation

Weighted score:

```text
weightedScore =
sum(
  criterionScore / 5 * criterionWeight
)
```

Example:

```text
Task Completion
4 / 5 * 30 = 24

Quality
4 / 5 * 25 = 20

Initiative
3 / 5 * 15 = 9

Communication
4 / 5 * 15 = 12

Problem Solving
3 / 5 * 15 = 9

Total = 74 / 100
```

Display:

```text
74 / 100
```

Do not display a letter grade in MVP.

# 49. Authorization Architecture

Create:

```ts
requireAuth()
requireRole()
requireMentorAccess()
requireInternOwnership()
```

Example:

```ts
const user = await requireAuth();

await requireMentorAccess({
  mentorId: user.id,
  internId
});
```

Do not rely only on middleware.

Resource-level authorization must happen close to the database operation.
